# License Server 技术文档

## 1. 项目概述

License Server 是一个基于 Spring Boot 3.x 的软件注册码激活管理系统，用于管理多个软件的授权激活。系统提供安全的激活码生成、设备绑定、加密通信和后台管理功能。

### 1.1 技术栈

- **Spring Boot 3.2.0** - 应用框架
- **Spring Data JPA** - 数据持久层
- **Spring Security** - 安全认证
- **H2 Database** - 内存数据库（开发/测试环境）
- **Thymeleaf** - 模板引擎（后台页面）
- **Java 21** - 编程语言
- **Lombok** - 代码简化

## 2. 核心功能实现

### 2.1 激活码生成

#### 2.1.1 生成算法

激活码使用 **SecureRandom** 生成加密安全的随机数，格式为 `XXXX-XXXX-XXXX-XXXX-XXXX`（25位，5组）。

```java
// 激活码字符集（去除易混淆字符）
private static final String CHAR_SET = "ABCDEFGHJKMNPQRSTUVWXYZ23456789";

// 生成随机激活码
private String generateRandomCode() {
    StringBuilder code = new StringBuilder();
    for (int i = 0; i < TOTAL_LENGTH; i++) {
        if (i > 0 && i % GROUP_LENGTH == 0) {
            code.append("-");
        }
        int index = secureRandom.nextInt(CHAR_SET.length());
        code.append(CHAR_SET.charAt(index));
    }
    return code.toString();
}
```

#### 2.1.2 HMAC-SHA256 签名

每个激活码都附带 HMAC-SHA256 签名，防止篡改：

```java
public String generateSignature(String code, Long softwareId, LocalDateTime expireAt,
                                 String planType, Integer maxDevices) {
    // 构建签名数据：code|softwareId|expireAt|planType|maxDevices
    String data = String.format("%s|%d|%s|%s|%d", code, softwareId, 
                                expireAt.format(DateTimeFormatter.ISO_LOCAL_DATE_TIME), 
                                planType, maxDevices);
    
    // 使用 HMAC-SHA256 签名
    Mac mac = Mac.getInstance("HmacSHA256");
    SecretKeySpec secretKey = new SecretKeySpec(keyBytes, "HmacSHA256");
    mac.init(secretKey);
    byte[] signatureBytes = mac.doFinal(data.getBytes(StandardCharsets.UTF_8));
    return bytesToHex(signatureBytes);
}
```

#### 2.1.3 激活码数据结构

- **code**: 激活码字符串（唯一）
- **softwareId**: 关联的软件ID
- **planType**: 套餐类型（basic/pro/enterprise/trial）
- **expireAt**: 过期时间
- **maxDevices**: 最大允许激活设备数
- **signature**: HMAC-SHA256 签名

### 2.2 设备绑定

#### 2.2.1 机器码生成

机器码由 CPU序列号、主板序列号、硬盘序列号和 MAC 地址通过 SHA-256 哈希生成：

```java
public String generateMachineCode(String cpuSerial, String motherboardSerial,
                                   String diskSerial, String macAddress) {
    String hardwareInfo = String.format("%s|%s|%s|%s",
            nullToEmpty(cpuSerial),
            nullToEmpty(motherboardSerial),
            nullToEmpty(diskSerial),
            nullToEmpty(macAddress));

    MessageDigest digest = MessageDigest.getInstance("SHA-256");
    byte[] hash = digest.digest(hardwareInfo.getBytes(StandardCharsets.UTF_8));
    return bytesToHex(hash);  // 64位十六进制字符串
}
```

#### 2.2.2 绑定逻辑

1. 客户端提交硬件信息和激活码
2. 服务器生成机器码
3. 检查机器码是否已被拉黑
4. 检查激活码是否有效（未过期、未封禁、未达设备上限）
5. 创建设备绑定记录
6. 更新激活码的已激活设备数

### 2.3 加密通信

#### 2.3.1 AES-256-GCM 加密

客户端与服务器之间的所有通信均使用 AES-256-GCM 加密：

```java
public String encrypt(String plaintext) {
    // 生成随机 nonce（12字节）
    byte[] nonce = new byte[GCM_NONCE_LENGTH];
    secureRandom.nextBytes(nonce);

    // 创建 GCM 参数规范
    GCMParameterSpec gcmSpec = new GCMParameterSpec(GCM_TAG_LENGTH, nonce);

    // 初始化加密器
    Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
    cipher.init(Cipher.ENCRYPT_MODE, secretKey, gcmSpec);

    // 执行加密
    byte[] ciphertext = cipher.doFinal(plaintext.getBytes(StandardCharsets.UTF_8));

    // 组合：nonce + ciphertext，Base64编码
    ByteBuffer buffer = ByteBuffer.allocate(nonce.length + ciphertext.length);
    buffer.put(nonce);
    buffer.put(ciphertext);
    return Base64.getEncoder().encodeToString(buffer.array());
}
```

#### 2.3.2 防重放攻击

通过时间戳和 nonce 验证防止重放攻击：

```java
public boolean validateRequest(long timestamp, String nonce) {
    // 检查时间戳是否在容忍范围内（默认5分钟）
    long now = System.currentTimeMillis();
    long diff = Math.abs(now - timestamp);
    if (diff > timestampTolerance) {
        return false;  // 时间戳过期
    }

    // 检查 nonce 是否已被使用
    String nonceKey = timestamp + ":" + nonce;
    if (usedNonces.putIfAbsent(nonceKey, now) != null) {
        return false;  // nonce 已存在，可能是重放攻击
    }

    return true;
}
```

**nonce 清理机制**：后台线程每10分钟清理过期的 nonce 记录。

## 5. 安全设计

### 5.1 通信安全

#### 5.1.1 AES-256-GCM 加密

- 使用 AES-256-GCM 模式，提供加密和认证功能
- 每次请求使用不同的随机 nonce（12字节）
- 认证标签长度 128 位
- 密钥长度 256 位

#### 5.1.2 防重放攻击

- 时间戳验证：请求时间戳与服务器时间差必须在 5 分钟内
- nonce 唯一性验证：每个 nonce 只能使用一次
- nonce 清理：后台线程定期清理过期的 nonce 记录

### 5.2 数据安全

#### 5.2.1 激活码签名

- 使用 HMAC-SHA256 对激活码数据进行签名
- 签名数据包含：code、softwareId、expireAt、planType、maxDevices
- 防止激活码被篡改

#### 5.2.2 机器码绑定

- 一机一码绑定，换设备需要重新激活
- 机器码由 CPU、主板、硬盘、MAC 地址哈希生成
- 支持设备拉黑功能

#### 5.2.3 管理员认证

- 使用 Spring Security 进行认证
- 密码使用 BCrypt 强哈希算法
- 表单登录 + Session 管理

### 5.3 密钥管理

#### 5.3.1 加密密钥

- AES-256 加密密钥可通过 `license.encryption.key` 配置
- 未配置时自动生成随机密钥（重启后失效，仅用于测试）
- 生产环境必须配置固定密钥

#### 5.3.2 签名密钥

- HMAC 签名密钥可通过 `license.signing.key` 配置
- 未配置时使用随机密钥

## 7. 客户端集成指南

### 7.1 集成流程

1. **收集硬件信息**：CPU序列号、主板序列号、硬盘序列号、MAC地址
2. **生成机器码**：使用 SHA-256 哈希硬件信息
3. **加密通信**：使用 AES-256-GCM 加密请求数据
4. **发送请求**：包含时间戳和 nonce
5. **处理响应**：解密并验证响应数据

### 7.2 请求示例

```java
// 1. 准备请求数据
Map<String, Object> request = new HashMap<>();
request.put("code", "ABCDE-FGHIJ-KLMNO-PQRST-UVWXY");
request.put("softwareId", 1);
request.put("cpuSerial", getCpuSerial());
request.put("motherboardSerial", getMotherboardSerial());
request.put("diskSerial", getDiskSerial());
request.put("macAddress", getMacAddress());
request.put("osInfo", System.getProperty("os.name"));
request.put("deviceName", getDeviceName());
request.put("timestamp", System.currentTimeMillis());
request.put("nonce", generateNonce());

// 2. 加密请求
String json = objectMapper.writeValueAsString(request);
String encrypted = aesEncrypt(json, encryptionKey);

// 3. 发送请求
Map<String, String> body = Map.of("data", encrypted);
ResponseEntity<Map> response = restTemplate.postForEntity(
    "http://localhost:8088/api/license/activate", 
    body, 
    Map.class
);

// 4. 解密响应
String encryptedResponse = (String) response.getBody().get("data");
String decryptedResponse = aesDecrypt(encryptedResponse, encryptionKey);
```

## 8. 常见问题

### 8.1 激活码无效

- 检查激活码是否输入正确（区分大小写）
- 检查激活码是否已过期
- 检查激活码是否已被封禁
- 检查激活码与软件ID是否匹配

### 8.2 设备无法激活

- 检查设备是否已被拉黑
- 检查是否已达到最大设备数限制
- 检查硬件信息是否完整

### 8.3 加密通信失败

- 检查加密密钥是否正确
- 检查时间戳是否在有效范围内
- 检查 nonce 是否唯一
